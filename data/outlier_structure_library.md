# 아웃라이어 글 구조 라이브러리 (누적 — 계속 추가, 절대 새로 안 만들고 버리지 않음)

**규칙 (2026-10-17 사용자 지시):** 반응 좋은 글을 리서치할 때마다 매번 새 날짜 파일을 만들고
끝내지 않는다. 찾은 구조는 **카테고리별로 여기에 계속 쌓는다.** 리서치 세션이 끝나도 이 파일은
안 끝난다 — 다음에 또 리서치하면 같은 카테고리 밑에 새 항목을 추가하거나, 새 카테고리가 필요하면
섹션을 새로 만든다. 상세 전체 분석(장면 단위 워크스루 원문)은 `data/outlier_structure_YYYY-MM-DD.md`
같은 날짜 파일에 남기고, 이 파일에는 **구조 요약 카드**만 쌓는다(출처 날짜 파일을 링크로 남겨서
원문을 추적할 수 있게 한다).

새 항목을 추가할 때 카드 형식:
```
- **[핸들] 플랫폼, YYYY-MM-DD 발견** — 팔로워 N / 조회수 N / 배율 N배
  - 훅: ...
  - 본문: ...
  - 마무리: ...
  - 출처: data/outlier_structure_YYYY-MM-DD.md
```

## 카테고리 G — 무얼굴 몽타주형 (실물 출연 없이 가능, 2026-10-18 추가)

**발견 배경:** 사용자가 "실물촬영은 싫다"고 해서, 얼굴/나레이션 없이도 터지는 포맷만 따로
vidIQ로 리서치함(Instagram+TikTok, 조회 10만+, 여행/라이프스타일 니치, format=style 지정).
15건 이상에서 반복 확인된 공통 레시피:

- **훅(0~3초):** 장면 1개 + 화면 중앙 고정 텍스트 한 줄(예: "Villages in SWITZERLAND",
  "12 PLACES TO VISIT IN PRAGUE", "how lucky are we"). 복잡한 설명 없이 장소/주제명만.
- **본문:** **여러 개의 짧은 클립을 음악 박자에 맞춰 빠르게 컷 전환**(한 영상을 15~30초
  그대로 늘어뜨리는 게 아니라 보통 5~10개 장면을 이어붙임) — "footage compilation" /
  "b-roll montage" 스타일.
- **오디오:** 대부분 **"Music only"** — 나레이션도 TTS도 없음. 트렌디하거나 감성적인
  음악이 분위기를 전담.
- **마무리:** 저장/팔로우 유도("Save our mini guide", "Follow for more") 또는 댓글
  유도("Comment LINK")가 자주 붙지만, 없어도(그냥 몽타주로 끝) 터지는 경우도 많음.
- **리스트형 변형(우리 주제와 바로 연결됨):** @kelseyinlondon "12 PLACES TO VISIT IN
  PRAGUE", @dylanvsearth "Places On Earth That Don't Feel Real" — 숫자 매긴 장소/항목을
  각각 짧은 클립+텍스트로 보여주는 구조. "공항에서 서울 가는 4가지 방법"처럼 우리가 이미
  쓰는 순위/리스트 소재를 몽타주 버전으로 바로 재활용 가능.
- **근거 수치 일부:** @swissbucketlists 256배(270만 조회/20.6만 팔로워), @kelseyinlondon
  10배(92만 조회), @arjsun 18배(150만 조회) 등. 전부 "effort: within a day/hour"로
  표기돼 있어 제작 난이도가 낮다고 분류됨(사람이 직접 찍은 영상 기준 — 우리는 스톡 영상을
  대신 쓰므로 난이도는 더 낮음).

**우리 파이프라인과의 차이(핵심 개선 포인트):** 지금 `lib/media/mix_audio.js`는 **영상
1개를 소스로 받아 그걸 루프/트림**해서 15~30초를 채운다 — 이 카테고리의 "여러 장면을
리듬감 있게 잇는다"는 핵심 요소가 아예 없다. 장면 수가 1개뿐이라는 게 "허접함"의 더 깊은
원인일 수 있음(자막 커버리지 문제와는 별개).

- 출처: vidIQ `vidiq_instagram_tiktok_outlier_search` (format=template 임베딩, 2026-10-18)
- **적용됨 (2026-10-18)**: `lib/media/mix_audio.js`의 `buildAestheticMontage` + `attach_topic_music.js`의
  `attachAestheticMontage`로 코드 반영. `queue_topic.js`가 클립 2개 이상 찾으면 이 경로로 감.
  로컬 ffmpeg 합성 테스트로 검증(RED→BLUE→GREEN→YELLOW 전환 + 훅 텍스트 유지 확인). 실제
  Pexels 다중 클립 end-to-end 발행 결과는 다음 확인 포인트.

**중요한 제약 발견(2차 검색, 2026-10-18):** "실물 없이 + 정보 전달형"을 따로 찾아봤는데,
"이거 왜 이래?"류 정보/문화 설명 콘텐츠는 @aakanksha.monga, @hayanleekr, @teliksmith 등
**거의 전부 실물 출연자가 직접 말함**(talking head)이었다. 얼굴 없이 터진 건 전부 카테고리 G
(미학 몽타주)였고 정보량은 거의 0에 가까웠다(위치명/제목 한 줄 정도). 즉 "실물 없이 +
실용정보"를 동시에 만족하는 대형 히트 사례는 이 리서치에서 못 찾았다 — 실물을 포기하면
콘텐츠 성격도 "정보 전달"에서 "미학/감성"으로 같이 옮겨가야 할 가능성이 높다는 뜻.
사용자가 "팔로우·조회수가 목적"이라고 명시했으므로, 이 트레이드오프를 사용자에게 그대로
전달하고 방향을 물어야 함(실용정보 브랜드 유지 vs 조회수용 미학 콘텐츠로 일부 전환).
